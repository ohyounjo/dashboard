# 임베드 기간 필터 권한 설계

[이슈 #49](https://github.com/ohyounjo/dashboard/issues/49)의 설계안이다. 사용자는 2026-11-21에 `can_time_range on Api` 확대를 승인했다. 이 문서는 결정 전 기준선과 구현·검증 계획을 보존한다. 판단 근거는 [Superset 계약 5절·12-3절·13절](../contracts/superset-notes.md)이며, 아래 구현과 검증은 허용 결정 이후에 진행한다.

## 현재 동작과 결정

변경 전 `EmbedGuest`는 `CurrentUserRestApi`, `Dashboard`, `Chart`의 `can_read` 세 권한을 갖는다. 기간 필터의 기본값은 적용되지만 선택 창의 `GET /api/v1/time_range/`가 403을 반환하여 값을 바꿀 수 없다. 시간 조건이 있어야 필터가 차트에 적용되며, 번들은 기간 필터가 있는 대시보드의 축약 차트에 필요한 `TEMPORAL_RANGE` 조건을 추가한다. 원본 차트의 시간 조건까지 자동으로 보장하는 것은 아니다.

| 선택 | 사용자 경험과 처리 |
|---|---|
| 허용 | `can_time_range on Api`를 추가해 기간 선택을 제공한다. 아래 권한 경계와 실제 임베드 동작을 확인한 뒤 계약에 반영한다. |
| 보류 또는 불허 | 기존 세 권한과 기본값만 적용되는 현재 동작을 유지한다. 결정과 이유를 이슈에 기록한다. |

권고는 **허용**이다. Superset 6.1.0 실측에서 해당 메서드는 날짜 문자열을 해석했고 데이터·메타데이터 접근은 관찰되지 않았다. 같은 `Api` 뷰의 `form_data`는 여전히 403이었다. 이는 확인한 버전과 설정에서의 결과이지 모든 설정에 대한 보장은 아니다. 기존에도 guest는 자기 대시보드 데이터셋 안에서 요청의 지표와 열을 바꿀 수 있으므로, 노출 가능한 열만 `dash` 뷰에 두어야 한다([계약 4절](../contracts/superset-notes.md)). `DASHBOARD_RBAC`, `GLOBAL_ASYNC_QUERIES`, `ENABLE_TEMPLATE_PROCESSING` 활성 구성과 `rls_rules` 토큰은 13절의 미검증 범위로 남긴다.

## 허용 시 변경

1. `superset/init_guest_role.py`의 `REQUIRED`에 `("can_time_range", "Api")`만 추가한다. `can_read on TimeRange`는 6.1.0에서 존재하지 않는 권한이다. 초기화는 `superset init` 다음에 실행하며, 기존처럼 권한을 정확히 맞추고 누락된 권한은 실패로 보고한다. `can_explore_json on Superset`은 이 결정의 범위가 아니다.
2. `contracts/superset-notes.md` 5절과 12-3절을 새로운 실제 동작에 맞춘다. 13절은 실측 당시 조건을 보존하면서 현재 결정과 연결한다. `reference/enhancement-report.md` 등 관련 설명도 확인해 오래된 권한 이름과 현재 제한을 정정하되, 검증하지 않은 동작은 보장하지 않는다.
3. 격리된 테스트 스택에서 초기화를 다시 실행하고 실제 `EmbedGuest` 권한이 네 개로 수렴하는지, 재실행해도 같은지 확인한다. 누락 권한 시 실패하는 기존 동작을 유지한다. 실제 배포에서는 변경된 초기화가 실행되어야 기존 역할에 반영된다. 운영 적용 시점과 결과를 기록한다.

## 검증 계획

기존 개발 스택과 데이터를 건드리지 않는 격리 스택에서 Superset 6.1.0과 guest token을 사용한다. 토큰은 대시보드 하나에만 발급하고 테스트 결과에 토큰이나 비밀값을 남기지 않는다. 권한 변경 전후의 결과와 버전·설정을 기록한다.

| 대상 | 기대 결과 |
|---|---|
| `GET /api/v1/time_range/`, 유효한 기간 문자열 | 변경 전 403, 변경 후 200 및 해석된 기간 응답. 잘못된 문자열은 400. |
| `GET /api/v1/form_data/`에 다른 대시보드 차트 ID | 변경 후에도 403. 같은 뷰의 다른 메서드가 열리지 않아야 한다. |
| 자기 대시보드 및 차트 데이터 | 기존대로 조회 가능. |
| 다른 대시보드와 그 차트, 자기 차트에 다른 데이터셋을 넣은 요청 | 기존 권한 경계 유지. 다른 대시보드는 403 또는 404, 차트·데이터셋 교차 요청은 거부. |
| 서브쿼리, CSV, 쓰기 요청 | 기존 차단 유지. 기존 데이터셋 내부의 임의 열·지표 접근 한계는 그대로 남는다. |
| 실제 웹앱 임베드의 기간 필터 | 시간 열과 범위 안팎의 데이터가 있는 축약 차트에서 기본 기간의 결과를 확인하고 다른 기간을 선택·적용한다. `time_range` 200, 차트 재조회와 데이터 변화 및 필터 범위 밖 차트의 유지 여부를 확인한다. |

`tests/test_api.py`에 기간 해석과 `form_data` 검사를 추가하고 기존 guest 권한 경계 테스트를 실행한다. 다른 데이터셋 검사는 조건부 건너뛰기로 통과하지 않도록, 내 대시보드에 없는 데이터셋과 다른 대시보드 차트가 실제로 존재하는 fixture를 확보한다. 단위 테스트와 `make test`를 실행하고 브라우저 확인의 요청·결과를 별도로 기록한다. 응답 코드만으로 필터 적용이나 데이터 격리를 증명했다고 판단하지 않는다.

## 되돌리기와 완료 조건

검증 실패나 운영상 문제가 있으면 `REQUIRED`에서 추가 권한을 제거하고 변경된 초기화를 다시 실행해 정확히 세 권한으로 수렴시킨다. 같은 guest token의 다음 기간 요청이 403이고 기본 기간이 적용되는지 확인한다. 역할 권한은 6.1.0 실측에서 다음 요청부터 반영됐지만, 운영 환경에서도 확인한다. 롤백 결과와 남은 사용자 영향은 이슈에 기록한다.

- [x] 사용자가 허용을 명시적으로 결정하고 이슈에 기록했다.
- [x] 초기화, 계약과 관련 설명을 변경하고 네 권한의 멱등성을 확인했다.
- [x] API 경계와 실제 임베드의 기본 기간·변경·재조회를 검증하고 아래에 기록했다.
- 보류·불허 경로는 허용 결정으로 해당하지 않는다.

## 구현 검증 결과 (2026-11-21)

- 격리 스택의 Superset 6.1.0에서 초기화와 재실행 모두 정확히 네 권한을 확인했다. guest API는 유효한 기간에 200, 잘못된 기간에 400, 다른 대시보드 차트의 `form_data`에 403을 반환했다. 기존 대시보드·데이터셋·서브쿼리·CSV·쓰기 경계도 회귀 테스트로 확인했다.
- 실제 웹앱에 임베드한 갤러리 사본에서 기간 필터 범위를 상자 수 차트 하나로 제한했다. 기본 기간 `2026-01-01 : 2026-07-01`에서 상자 수 2,876, 범위 밖 무게 34,214를 확인했다. `2026-03-01 : 2026-04-01`로 바꾸고 적용하자 기간 해석과 차트 재조회가 200이고 상자 수는 366으로 바뀌었으며 무게는 34,214로 유지됐다.
- `make test-unit`과 빈 테스트 DB의 `AUTH_COOKIE_SECURE=0 make test KEEP=1`이 통과했다. 초기 테스트 작성 시 Rison 요청 형식 오류를 수정했으며, 중간 재실행은 보존한 테스트 DB의 과거 조회 기록으로 통계 검사에 실패하여 빈 볼륨에서 다시 실행했다. 운영 배포·운영 환경 확인은 수행하지 않았다.
