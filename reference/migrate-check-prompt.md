# 이슈 #57 구현 오케스트레이션 프롬프트

설계 PR을 병합한 뒤 새 세션에서 실행한다. [설계서](migrate-check-design.md)

```text
# 목표
ohyounjo/dashboard 이슈 #57을 해결하고 검토 가능한 구현 PR을 만든다. 실제 확인하지 않은 결과를 성공으로 기록하지 않는다.

# 시작
- AGENTS.md, 이슈 #57의 최신 본문·댓글, reference/migrate-check-design.md, contracts/README.md의 설정 버전과 migrate 절, dashkit/migrate.py, dashkit/__main__.py, tests/test_migrate.py 및 reference/enhancement-report.md의 관련 문장을 읽는다. 현행 계약과 이슈의 검사 결과 요구가 충돌한다는 점을 확인하고 차이를 보고한다.
- 최신 origin/main의 SHA를 기록하고 격리 worktree와 브랜치를 준비한다. 다른 세션의 변경·컨테이너·데이터를 건드리지 않는다. 비밀값은 환경 변수로만 취급한다.

# 조사와 구현
1. 원본 예시의 두 설정 파일 바이트와 git 상태를 보존하면서 격리 환경에서 make migrate CHECK=1을 실행한다. 출력, 종료 코드, 환경, SHA와 파일 불변성을 기록한다. 필요 시 Docker가 아닌 동등한 CLI 실행을 보조 증거로 삼고, make 자체를 실행하지 못한 이유는 별도로 밝힌다.
2. 보고가 재현되면 설계서의 동작 표에 따라 검사에서 현재 버전의 생략된 키는 성공으로 판단한다. 일반 migrate의 명시적 버전 삽입은 보존하고 실제 구버전 변환은 검사 실패로 보고한다. 오류 수집과 변환 전 두 파일 검증, 텍스트 보존 및 파일 불변성을 유지한다. 검사와 일반 모드가 다르므로 contracts/README.md와 CLI 도움말을 함께 갱신한다. 재현되지 않으면 원인과 확인 근거를 남기고 오래된 보강 보고서를 수정한다.
3. CLI의 종료 코드·표준 출력/오류·양쪽 파일 바이트를 회귀 검증한다. 키 생략, 명시적 v1, 혼합, 임시로 설정한 현재 v2의 등록된 v1→v2 변환 및 미등록 변환, 잘못된 버전과 미래 버전, YAML 오류와 한 파일 실패를 포함한다. 일반 모드의 삽입·변환·멱등성과 기존 세 예시를 변경 없이 확인한다. migrate는 내용 스키마 검사 자체가 아님을 유지한다.
4. 관련 테스트, 필요한 단위 검사와 git diff --check를 실행하고 결과 및 실행하지 못한 검증을 기록한다. 완료 조건이나 범위가 바뀌면 이슈를 갱신한다.

# 제출
- 한국어 PR 템플릿에 변경 이유, 계약 변경, 재현 증거, 검증 및 남은 제한을 기록한다. 완료 조건이 충족된 경우에만 이슈 종료 키워드를 사용한다. 리뷰 지적을 해결하고 저장소의 승인·체크 요구를 따른다.
- 사용자에게 PR, 기준 SHA, 재현과 테스트 결과 및 미완료 사항을 보고한다.
```
