# 개발 프로세스 대시보드 구현 계획 (기존 Artifact 버전)

> 작성일: 2026-11-19 · 상태: **구현 완료된 이전 버전의 계획서.** 결과물은 `reference/index.html`이다.
>
> 현재 프로젝트의 설계는 `reference/plan.md`(Superset 임베드형 범용 템플릿)다. 이 문서는 참고용으로만 둔다.
> - **지금도 기준인 절:** 6절 디자인 시스템, 7절 모션 원칙. 5절 화면 구성은 예시 프로젝트 `devtracker`의 화면 기준이다.
> - **plan.md로 대체된 절:** 2절 권한(보기 전용 원칙만 유지), 3절 파일 구조, 4절 `DATA` 객체(CSV와 `schema.yaml`로 이동), 8~10절 운영·구현·검증.
> - 이 문서의 `dashboard/` 경로는 지금의 `reference/`를 가리킨다.

## 1. 목표와 범위

스마트홈 앱 프로젝트(더미)의 개발 진행 상황을 한 화면에서 추적하는 웹 대시보드를 만들고, Claude Artifact로 게시해 팀원과 공유한다.

| 구분 | 포함 | 제외 |
|---|---|---|
| 데이터 | 코드 안에 넣은 더미데이터 | 외부 API, 플러그인(Jira·Linear·Notion 등), 공유 DB |
| 기능 | 개요, 일정, 이슈, 문서 4개 화면과 필터·정렬·검색, 다크모드 | 페이지 안에서 데이터 수정 |
| 검증 | 데이터 무결성 확인(ID 연결, 날짜 순서) | UI 테스트(사용자가 직접 확인) |

## 2. 확정된 결정 사항

| 항목 | 결정 |
|---|---|
| 권한 | **정적 페이지.** 페이지 안에 수정 UI를 두지 않는다. 게시자만 `data` 객체를 고쳐 다시 게시하고, 팀원에게는 Artifact를 보기 전용으로 공유한다. |
| 보기 사용자 | **완전 잠금.** 칸반 드래그와 상태 변경을 막고, 필터·정렬·검색·탭 이동만 허용한다. |
| 더미 주제 | **스마트홈 앱.** `module_3-smarthome`과 같은 주제로 맞춘다. |

## 3. 산출물과 파일 구조

```
dashboard/
├─ plan.md           # 이 문서
└─ index.html        # Artifact로 게시할 단일 파일(HTML+CSS+JS, 데이터 포함)
```

- 라이브러리 없이 바닐라 JS로 만든다. 차트는 SVG로 직접 그린다.
- 폰트: Google Fonts의 Pretendard 대체로 **Noto Sans KR**(본문)과 **Space Grotesk**(숫자·제목), 숫자는 `tabular-nums`.

## 4. 더미데이터 설계

JS 객체 `DATA` 하나에 모든 데이터를 담고, ID로 서로 연결한다.

```js
const DATA = {
  project:   { name, startDate, endDate, today: "2026-11-19" },
  members:   [{ id: "m1", name, role }],                         // 6명
  milestones:[{ id: "ms1", title, start, end, status, progress }],// 5개
  tasks:     [{ id, title, column, assignee, milestoneId }],     // 칸반 카드 16개
  issues:    [{ id: "ISS-101", title, severity, status, assignee, milestoneId, created, updated }], // 24개
  docs:      [{ id, title, type, version, author, updated, milestoneId }], // 8개
  kpiHistory:[{ week, openIssues, doneTasks }]                   // 최근 6주, 증감 계산용
};
```

| 항목 | 값 |
|---|---|
| 마일스톤 | M1 요구사항·설계 → M2 기기 연동(Wi-Fi/Matter) → M3 자동화 루틴 → M4 베타 테스트 → M5 정식 출시 |
| 마일스톤 상태 | `done`, `in-progress`, `planned`, `delayed` |
| 칸반 컬럼 | To Do, In Progress, Review, Done |
| 이슈 심각도 | `critical`, `major`, `minor`, `trivial` |
| 이슈 상태 | `open`, `in-progress`, `resolved`, `closed` |
| 문서 유형 | 기획안, PRD, 기술 설계, 회의록 |

데이터 규칙: 모든 `milestoneId`와 `assignee`는 실제로 있는 ID를 가리키고, `start ≤ end`, 문서 버전은 `v1.0` 형식을 따른다.

## 5. 화면 구성

### 5-1. 공통 레이아웃: Navigation Rail
- 왼쪽에 폭 72px 세로 Rail을 두고, 아이콘과 짧은 라벨로 **개요 / 일정 / 이슈 / 문서**를 배치한다. 선택된 항목은 메인 컬러 알약형 배경으로 표시한다.
- Rail 하단에 다크모드 전환 버튼을 둔다.
- 폭 600px 이하에서는 Rail이 화면 하단 탭 바로 바뀐다.
- 탭마다 `#overview`, `#schedule`, `#issues`, `#docs` 주소를 붙여 링크로 공유할 수 있게 한다.
- 상단 헤더에 프로젝트 이름, 기준일, "보기 전용" 표시를 둔다.

### 5-2. 개요
- KPI 카드 4개: 전체 진척률, 열린 이슈 수, Critical 이슈 수, 다음 마일스톤까지 남은 일수
- 각 카드에 지난주 대비 증감을 📈/📉와 ▲▼ 숫자로 표시한다. 좋아진 방향은 초록, 나빠진 방향은 빨강.
- 차트 2개: 마일스톤별 진척률 막대, 주간 열린 이슈 추이 선(6주)
- 다가오는 마일스톤 목록과 최근 갱신된 이슈 5건

### 5-3. 일정
- **마일스톤 타임라인:** 간트 형태의 가로 막대. 진행률만큼 채우고, 오늘 위치에 세로선을 긋는다. 상태는 ✅ 완료, 🔄 진행, ⏳ 예정, ⚠️ 지연으로 표시한다.
- **칸반보드:** 4개 컬럼, 카드에 담당자·마일스톤 칩. 드래그는 막는다. 마일스톤 필터 하나를 둔다.

### 5-4. 이슈
- 필터: 심각도, 상태, 담당자(다중 선택 칩) + 제목 검색
- 테이블 열: ID, 제목, 심각도, 상태, 담당자, 연결 마일스톤(칩), 수정일. 열 머리글을 눌러 정렬하고, 방향은 🔼/🔽로 표시한다.
- 해결 여부는 ✅/❌로 표시한다.
- 결과 건수와 "필터 초기화" 버튼을 둔다. 좁은 화면에서는 표만 가로 스크롤한다.

### 5-5. 문서
- 기획안·PRD 등 유형 필터
- 목록 열: 제목, 유형, 버전, 작성자, 최종 수정일, 연결 마일스톤
- 최근 7일 안에 수정된 문서에는 🆕 표시를 붙인다.

## 6. 디자인 시스템

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--primary` | `#1428A0` | `#7B8CFF` (어두운 배경에서 읽히도록 밝게) |
| `--bg` | `#F5F6FB` (남색 기운의 회색) | `#0E1120` |
| `--surface` | `#FFFFFF` | `#171B2E` |
| `--fg` / `--muted` | `#141833` / `#5B6080` | `#E7E9F5` / `#9AA0BE` |
| `--good` / `--warn` / `--bad` | 초록 / 주황 / 빨강 | 각각 밝은 톤 |

- **심각도 색:** Critical 빨강, Major 주황, Minor 파랑, Trivial 회색. 색에 더해 텍스트 라벨도 함께 표시한다.
- **이모지 사용 범위:** O/X, 완료 체크, 방향, 증감에만 쓴다. 섹션 제목 장식에는 쓰지 않는다.
- **다크모드:**
  - 처음에는 시스템 설정을 따르고, 버튼으로 바꿀 수 있다.
  - 선택한 값은 `localStorage`에 저장하되, 읽기·쓰기를 try/catch로 감싼다.
  - Artifact 규칙대로 `:root`, `prefers-color-scheme`, `[data-theme]` 세 단계 토큰 구조로 만든다.

## 7. 모션 원칙

모션은 아래 표의 네 곳에만 쓴다. 각 모션은 화면이 처음 보이거나 필터가 바뀔 때 한 번만 실행된다.

| 대상 | 모션 | 시간 |
|---|---|---|
| KPI 수치 | 0에서 목표값까지 숫자 카운트업 | 800ms, ease-out |
| 막대·진척률 | 폭이 0에서 값까지 늘어남 | 600ms |
| 추이 선 차트 | 선이 왼쪽에서 오른쪽으로 그려짐(`stroke-dashoffset`) | 900ms |
| 탭 전환 | 4px 위로 이동하며 페이드인 | 200ms |

금지 사항:
- 반복 애니메이션, 패럴랙스, 바운스는 쓰지 않는다.
- `prefers-reduced-motion`이 켜져 있으면 모든 모션을 끄고 최종값을 바로 보여준다.
- 화면은 애니메이션 없이도 완성된 상태로 보여야 한다. `opacity: 0`에서 기다리는 상태를 만들지 않는다.

## 8. 권한 운영 방법

1. 게시자가 `index.html`의 `DATA` 객체를 수정한다.
2. 같은 파일 경로로 Artifact를 다시 게시한다. 링크는 바뀌지 않는다.
3. 팀원에게는 claude.ai의 Artifact 공유 설정에서 **보기 권한**으로 링크를 전달한다.
4. 이미 페이지를 열어 둔 팀원 화면에도 다시 게시한 내용이 자동으로 반영된다.

## 10. 검증 범위

UI는 사용자가 직접 확인하므로 자동 테스트에서 뺀다. 게시 전에는 아래만 확인한다.
- 스크립트 문법 오류가 없는지 한 번 확인한다.
- 데이터 무결성: ID 참조가 깨지지 않았는지, 날짜 순서가 맞는지 스크립트로 한 번 확인한다.
- KPI 계산 함수에 샘플 입력을 넣어 결과를 한 번 확인한다.
