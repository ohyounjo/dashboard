# 이슈 #54 화면 검증 기록

2026-11-21, 격리 복사본과 별도 Compose 프로젝트에서 `apache/superset:6.1.0`, embedded SDK 0.4.0, 실제 웹앱 guest 토큰과 Chromium으로 확인했다. 한글 글꼴은 격리 환경에만 제공했다. 화면은 390px과 1280px, 라이트와 다크다.

`before-*`는 devtracker 개요의 기존 배치, `after-*`는 chart-gallery의 구현 후 차트 갤러리이므로 같은 화면의 전후 비교는 아니다. `before-metrics.json`, `after-metrics.json`은 화면별 iframe과 차트 폭이다. 구현 후 devtracker 개요에서 900px iframe 적용 전후 같은 배치의 카드·차트·표 폭은 각각 69→205px, 97→279px, 154→426px로 측정했다. 1280px 기존 iframe은 1158px이었다.

별도 chart-gallery 배치·필터 대시보드에서 숫자 범위 하한 5→10 적용 후 상자 수 2,876→2,821, 무게 34,214→33,554, 출하 123→116으로 바뀌었고 390→1280→390 전환 후 유지됐다. 대시보드 내부 탭 전환, 접근 가능한 스크롤 영역의 방향키와 터치 스와이프를 확인했다. `after-horizontal-touch.json`은 터치 측정이다. 표나 긴 문자열은 추가 스크롤이 필요하고 모바일에서 한 화면에 전체 배치가 보이지 않는다.

수정 전 자동 높이 필터 패널을 열면 높이가 계속 늘어나는 문제가 기존 HEAD 및 기존 356px iframe에서도 재현됐다. 예를 들어 고정 390px 뷰포트에서 3초 간격으로 1425→1461→1479→1515→1533→1569→1587→1623px이었다. Superset 패널이 iframe 높이보다 18px 더 내려가 SDK 측정이 피드백을 만든 것으로 관찰했다. 고정 높이에서는 폴링하지 않는다. 수정과 추가 검증은 아래에 기록했다.

고정 높이 500px에서는 필터를 열어도 높이가 유지됐고, 브라우저의 스크롤 조작으로 내부 탭의 마지막 차트에 도달했다(`fixed-height.png`). 터치 세로 스와이프로 내부 스크롤은 움직였지만 툴팁이 문서 높이를 일시적으로 늘린 상태에서 마지막 콘텐츠를 편하게 조작할 수 있는지는 확인하지 못했다.

당시 `make test-unit`: Python 504 passed, JavaScript 43 passed, Studio 433 passed. 격리 복사본의 `make test`: devtracker 722 passed / 55 skipped, Studio 13 passed, 프로젝트 전환 15 passed, gallery 45 passed, 새 프로젝트 3 passed, 누적 데이터 15 passed. 독립 코드 검토에서 추가로 재현 가능한 계약·보안 결함은 발견하지 못했다. 당시 테스트만으로 자동 높이 및 터치 조작 제한을 해소하지는 못했다.

## 필터를 열었을 때의 높이 증가 수정

Superset 6.1.0의 열린 세로 필터 막대에 임베드 전용 대시보드 CSS를 적용해 높이를 iframe에 맞추고 내부 스크롤을 허용했다. 100% 높이는 Superset의 중간 요소 높이가 0이어서 적용 버튼을 가리는 부작용이 있었고 채택하지 않았다. `100vh`를 쓰는 최종 규칙은 격리 스택에서 실제 번들 sync 후 guest 화면으로 확인했다. 390px과 1280px에서 필터를 연 상태의 높이는 6회 측정 모두 1389px이었고, 필터 적용 후 값 2,821 및 내부 탭 전환을 확인했다. 테스트 코드는 `e2e/embed-height.mjs`다. 기존 Superset 대시보드에 적용하려면 `make sync`가 필요하며, Superset의 bootstrap과 DOM 구조가 바뀌면 재검증해야 한다. 이 시험은 폴링이 콘텐츠 감소 후 높이도 줄이는지 보장하지 않는다.

고정 높이 500px에서도 필터를 연 뒤 여섯 차례 모두 500px로 유지됐으며 필터 적용과 내부 탭 전환이 통과했다.

축소 수정 전 추가 확인: 자동 높이에서 내부 탭을 `농원별` → `과일·판매 경로별` → `농원별`로 바꾸면 1389 → 1469 → 1469px로, 콘텐츠가 줄어도 iframe은 줄지 않았다. 진단을 위해 iframe 높이를 잠시 200px로 낮추고 다시 측정하면 1389px로 돌아왔다. 따라서 높이가 무한 증가하는 문제와 별도로 높이 축소 문제를 확인했다. 고정 높이 500px에서 실제 터치 스와이프로 iframe 내부 scrollY가 0→969px로 움직여 마지막 행의 차트 제목이 세로 표시 범위에 들어왔다. 가로 스크롤을 포함한 추가 조작은 아래에 기록했다.

## 자동 높이 축소 수정

Superset 6.1.0의 `getScrollSize`는 `document.body.scrollHeight`를 반환하는데 기본 문서 높이가 iframe 높이에 묶여 축소를 막았다. 임베드에 한해 문서 높이를 콘텐츠 기준으로 바꾸고, 필터 막대의 높이 기준을 콘텐츠와 iframe 양쪽에 맞췄다. 브라우저의 `:has()`와 Superset의 bootstrap 및 필터 DOM 구조에 의존한다. 실제 번들 sync 후 390px과 1280px에서 필터를 연 채 탭 전환 시 1469→1389px로 줄었고 필터 적용도 통과했다. 500px 고정 높이는 탭 전환 후에도 유지됐다. 터치 에뮬레이션에서 필터를 접고 1409→1489→1409px을 확인했으며 고정 높이에서 마지막 행까지 세로 스와이프했다. `e2e/embed-height.mjs`가 열린 필터의 증가·축소 및 고정 높이를 회귀 검사한다. 기존 대시보드에 반영하려면 `make sync`가 필요하다.

## 최종 화면과 추가 조작 확인 (2026-11-22)

최종 CSS를 sync한 뒤 `final-devtracker-*` 네 화면을 같은 devtracker 개요의 `before-*`와 비교했다. 1280px 라이트·다크에서 iframe 폭 1158px, 차트 9개의 순서와 폭(270·365·555px 계열)이 같았다. 390px에서는 iframe 폭이 356→900px로 바뀌었고 같은 순서의 9개 차트 폭이 69·97·154px 계열에서 205·279·426px 계열로 늘었다. 네 화면 모두 브라우저 `pageerror`는 없었다. `final-devtracker-metrics.json`에 측정값을 남겼다. 가로로 이동해야 한 화면 밖의 차트를 볼 수 있으며 긴 라벨이나 표는 추가 스크롤이 필요하다.

갤러리의 막대 차트에서 돌담농장을 선택한 교차 필터는 상자 수 2,876→433, 무게 34,214→5,503, 건수 123→19로 바뀌었다(`cross-filter.png`). 고정 높이 500px에서 터치 에뮬레이션으로 마지막 행까지 세로 이동한 뒤 가로 스크롤 0→544px(오른쪽 끝)에 도달했다. 최소 높이 200px의 필터 적용과 내부 탭도 확인했다. 사용자는 devtracker에서 필터 적용·초기화를 직접 확인했다.

최신 `main` 기준 분리 브랜치에서 `make test-unit`은 Python 521개, JavaScript 43개, Studio 433개가 통과했다. 격리 스택의 최종 `make test`는 devtracker 738 passed / 55 skipped, Studio 13, 프로젝트 전환 15, chart-gallery 45, 새 프로젝트 3, 누적 데이터 15 passed로 종료했다. 최종 임베드 CSS와 guest 권한에 대한 독립 검토에서 추가로 재현 가능한 보안·계약 문제는 보고되지 않았다.
