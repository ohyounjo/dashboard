# 설정 버전 migrate 검사 설계

[이슈 #57](https://github.com/ohyounjo/dashboard/issues/57) · [실행 프롬프트](migrate-check-prompt.md)

## 기준과 계약 충돌

기준 조사 커밋은 `13d9642119bf78d1ef6ce9fdcd2889eb663af170`이다. `contracts/README.md`는 버전 생략을 버전 1로 인정하지만, 동시에 일반 `migrate`는 생략된 키를 추가하고 `--check`는 고칠 것이 있으면 1을 반환한다고 명시한다. 이슈의 생략된 현재 버전은 검사 통과라는 요구와 후자의 기존 계약은 충돌한다. 현재 계약상 기존 결과는 의도된 동작이다. 구현 PR에서 아래 제안으로 계약을 명시적으로 변경하기 전에는 현행 계약을 우선한다.

코드상 `migrate_text`는 키 삽입을 `steps`에 넣고 `cmd_migrate`는 그 단계가 있으면 검사 실패로 처리한다. `tests/test_migrate.py`에도 이 동작을 기대하는 테스트가 있다. 읽기 전용으로 작업 트리를 마운트한 기존 `dashkit-app:local` 이미지에서 `PROJECT=devtracker PROJECTS_DIR=/app/projects python -m dashkit migrate --check`를 실행한 결과 두 파일의 키 삽입이 표시되고 종료 코드 1을 반환했다. 파일은 읽기 전용 마운트로 보호했다. 이는 CLI 실측이며 `make migrate CHECK=1` 자체의 검증은 아니다. 구현 작업에서 최신 main과 실행 환경을 다시 확인한다.

## 제안하는 동작

버전 호환성 검사와 선택적인 명시적 키 삽입을 구분한다. `--check`는 버전 형식의 실제 이전이 필요한지만 판정하며 파일을 절대 쓰지 않는다. 일반 `migrate`의 기존 키 삽입 동작은 유지한다. 따라서 두 모드의 출력과 변경 필요 판단이 다름을 계약과 CLI 도움말에 명시한다. 이 제안은 설계이며 현행 계약을 변경하지 않는다.

| 파일의 버전 | `--check` 결과 | 일반 `migrate` |
|---|---|---|
| 키 생략, 현재 버전 1 | 성공 0, 최신 형식 안내; 삽입을 필수 변경으로 보고하지 않음 | 기존대로 `version: 1` 삽입 |
| 명시적 현재 버전 | 성공 0, 최신 형식 안내 | 변경 없음 |
| 구버전(미래에 현재 버전이 2 이상이고 변환 등록됨), 생략 포함 | 실패 1, 대상 파일과 실제 버전 변환 단계 안내 | 등록된 변환을 순서대로 적용하고 버전 갱신 |
| 1 미만, 정수가 아님, bool, 지원보다 높음, YAML 오류, 누락 파일 또는 변환 미등록 | 오류와 종료 1 | 오류와 종료 1; 변환 계획 실패 시 어느 파일도 쓰지 않음 |

두 파일을 독립 판정하고 하나라도 이전이 필요하거나 오류이면 전체 실패다. 오류 발생 시 다른 파일이 정상이어도 쓰지 않는다. 이 도구는 설정 내용의 스키마 유효성을 보장하지 않으므로 `dashkit check`와 혼동하지 않는다. 기존 텍스트 보존, BOM·문서 시작 표시·CRLF 처리와 일반 모드의 멱등성은 유지한다. 구버전 검사는 실제 버전을 올리지 않고 테스트에서 `CONFIG_VERSION`과 변환 함수를 격리해 시뮬레이션한다.

## 구현과 검증

- 구현 전 최신 main에서 예시 프로젝트의 파일 해시와 상태를 기록하고, 격리 환경에서 `make migrate CHECK=1`의 출력과 종료 코드를 확인한다. Docker가 불가하면 이유와 대체 CLI 검증 범위를 명시한다. 예시는 수정하지 않는다.
- 재현되면 삽입 단계와 실제 버전 변환 단계를 구분해 검사 결과를 계산한다. 구버전에서 생략된 키는 변환에 필요한 임시 텍스트에 삽입하되 검사에서는 쓰지 않는다. 기존 API 호출자와 오류 집계, 두 파일 처리 순서를 살핀다.
- `contracts/README.md`의 현재 삽입·검사 문장을 함께 수정하고 CLI 도움말과 필요하면 변경 기록을 맞춘다. 실제로 재현되지 않으면 원인과 결과를 기록하고 오래된 `reference/enhancement-report.md`의 관련 서술을 정정한다.
- 회귀 테스트는 실제 CLI 종료 코드 및 표준 출력/오류, 양쪽 파일의 바이트 불변성을 검증한다. 생략·명시적 v1·혼합, 등록된 가상 v1→v2 및 누락 변환, 잘못된 값(문자열·0·소수·bool·null)과 미래 버전, YAML 오류, 한 파일 오류를 포함한다. 일반 모드의 삽입·변환·재실행도 확인한다. 세 예시 프로젝트를 원본 그대로 검사한다.
- 변경 후 관련 테스트와 저장소 단위 검사를 실행하고 실패·미실행 이유와 실제 명령 결과를 PR에 남긴다. 재현 결과나 범위가 달라지면 이슈를 갱신한다.
