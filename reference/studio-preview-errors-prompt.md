# Studio 미리보기 오류 조사 오케스트레이션 프롬프트

설계 PR 병합 후 새 Codex 채팅에서 아래를 사용한다. [설계서](studio-preview-errors-design.md)

```text
# 목표

ohyounjo/dashboard 이슈 #51의 Studio 적용 중 차트 오류와 Superset 서비스워커 404를 조사한다. 각 요청의 조건과 사용자 영향을 분리해 재현하고 실제 결함이면 수정한다. 로그인, 미리보기, 접근 제어와 CSP를 유지하고 검증 결과를 구현 PR로 올린다.

# 시작

- AGENTS.md, 이슈 #51 본문과 댓글, reference/studio-preview-errors-design.md, contracts/studio.md, contracts/api.md의 현재 프로젝트, contracts/auth.md의 인증·임베드 계약을 읽는다. 계약과 이슈의 차이는 계약을 기준으로 알린다.
- 최신 main을 확인하고 다른 작업과 겹치지 않는 작업 공간과 codex/51-studio-preview-fix 브랜치를 준비한다. 기존 변경을 보존한다.
- make info와 Makefile의 TEST_ENV, _test_run, test-down을 확인한다. KEEP=1 make test로 격리된 테스트 스택을 준비하고 동일한 테스트 환경으로 Studio를 기동한다. 포트, Compose 프로젝트, .test 상태·빌드 경로, 테스트 전용 프로젝트 사본과 STUDIO_ORIGIN을 확인한다. 개발 스택이나 실제 데이터를 수정하지 않는다. 테스트 환경의 비밀값은 환경 변수로만 취급한다.

# 조사와 구현

1. 설계서 표의 네 사례를 각각 독립적으로 관찰한다. 브라우저 프레임별 URL, 메서드, 개시자, 상태/취소, 시각, 적용 단계와 사용자 증상을 연결한다. 버전, 재현 횟수 및 새/기존 브라우저 프로필을 기록하고 토큰·쿠키·민감 데이터를 증거에서 제거한다.
2. 서비스워커는 등록 주체와 경로, 이미지 내부 파일, 프록시와 브라우저의 기존 등록을 확인한다. 차트는 같은/다른 프로젝트 적용, 삭제 또는 교체되는 차트, 수동 새로고침과 전환을 비교해 sync 단계와 요청을 대조한다. 400과 404는 따로 분석한다. 로그인 전 401과 탐색 취소가 예상 동작인지 실제 화면으로 확인한다. 재현되지 않은 사례는 미확인으로 보고한다.
3. 근거로 확인된 결함만 원인에 맞게 수정한다. 서비스워커 404를 가짜 성공으로 바꾸거나 콘솔 오류를 일괄 억제하지 않는다. 적용 중 iframe 변경이 필요하면 성공·check/load/sync 실패·스트림 단절과 상태 복구·접기·프로젝트 전환·수동 새로고침까지 설계한다. 실패 시 마지막 sync 성공 프로젝트와 DB의 불일치 가능성을 숨기지 않는다. 정상적인 인증 검증, guest token, Host/Origin, CSP, SameSite와 읽기 전용 DB 계정 경계를 유지한다.
4. 원인에 맞는 회귀 테스트를 추가하고 가능하면 수정 전 실패와 수정 후 통과를 확인한다. 보안 경계와 프레임 정책도 검사한다. 동작이 바뀌면 관련 contracts 문서를 갱신한다. 이슈 범위나 완료 조건이 바뀌면 이슈를 갱신한다.
5. 1280px와 390px의 라이트/다크에서 로그인, 프로젝트 적용, 적용 후 차트를 검사한다. 390px에서 기본 접힘, 수동 미리보기 및 별도 창 웹앱을 확인한다. 다른 출처의 안내, 실패와 스트림 복구도 확인한다. 각 사례의 실제 결과와 남은 제약을 기록한다.
6. make test-unit, 격리된 make test, git diff --check를 실행한다. 실행이 막히면 복구를 시도하고 미실행 원인을 구체적으로 남긴다. 검사가 끝나면 해당 테스트 스택만 make test-down으로 정리한다.

# PR 및 보고

- 결과를 검토하고 커밋·푸시한 뒤 .github/pull_request_template.md를 따라 한국어 PR을 만든다. Refs #51로 연결한다. 조사 결과, 재현 증거, 수정 근거, 테스트와 미확인 사항을 기록한다. 미완료 조건이 있으면 draft로 올린다.
- 리뷰 지적은 최신 커밋과 대조하고 타당한 내용은 수정해 관련 검증을 다시 실행한다. 병합은 별도 지시를 따른다.
- PR 링크, 각 사례의 판정, 수행한 검사와 남은 제약을 보고한다.
```
